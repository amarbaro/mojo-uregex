# mojo-uregex v0.3.0

**Released:** 2026-10-08 · **Previous:** first release in this repository

## What it does

Unicode-aware regular expressions for Mojo, built for the pre-tokenizers of LLM
tokenizers (GPT-2, Llama 3, Qwen, DeepSeek, gpt-oss, Spark-X2.5) and checked
against Python's `regex` by differential testing. Pure Mojo, CPU. Build with
`-I src`; requires Mojo 1.1.

## Highlights

- 1.9 to 3.1x faster than Python `regex` on the tokenizer patterns (`tools/bench.sh`); slowest on plain-ASCII GPT-2 text.
- Two engines from one source: `Pattern` for tokenizers, `FullPattern` for capture groups, named groups, `\b` `\B` and fixed-length lookbehind.
- Byte offsets on UTF-8 input with no copy to codepoints; codepoint offsets on request.
- Unicode 18.0 general categories and case maps, generated from the Unicode Character Database by `tools/gen_unicode.mojo` and checked against Python `regex`.

## Changes

First release in this repository. Public API:


- `Pattern(src)`, `FullPattern(src)`: `findall`, `findall_spans`, `findall_cps_offsets`, `search`, `split_keep`; `FullPattern` adds `findall_groups`, `groups()`, `group_index(name)`.
- One-shot helpers `findall`, `search`, `split_keep`, `compile` (full syntax).
- Supported and rejected syntax: README, "Supported syntax".

## Known limits

- Backtracking engine: pathological patterns can be exponential.
- No backreferences, possessive quantifiers or variable-length lookbehind.
- `FullPattern` is slower than `Pattern` for the same pattern; use `Pattern` unless you need its syntax.
- Positions are Int32 internally: inputs over 2 GiB are not supported.
